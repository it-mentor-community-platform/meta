# Бизнес аналитика - работа студентов над проектами роадмапа

Функционал является частью личного кабинета студента платформы.

# Необходимый контекст

- Бизнес аналитика того как происходит учёт проектов, добавленных в систему любым из способов - [projects-bookkeeping.md](./projects-bookkeeping.md)
- Роадмапы:
  - [Java](https://zhukovsd.github.io/java-backend-learning-course/)
  - [Python](https://zhukovsd.github.io/python-backend-learning-course/)
  - [Go](https://zhukovsd.github.io/golang-backend-learning-course/)

## Термины и сущности

- "Тип проекта" - название проекта из ТЗ, например "симуляция". Один тип проекта может иметь несколько ТЗ для разных языков (Java, Python, Go)
- "Сдать проект" - отправить в систему ссылку с GitHub репозиторием на законченную реализацию. "Законченность" проекта субъективна и на ответственности студента. Получение ревью не является обязательным условием сдачи и не влияет на прогресс роадмапа.
- "Реализация проекта" - то, что сдаёт студент. Реализация описывается ссылкой на GitHub репозиторий. Каждая реализация относится ровно к одному типу проекта и имеет один основной язык программирования.

## Контекст и бизнес правила

### Проекты и их ТЗ

- Список типов проектов - фиксированный. "Виселица", "симуляция", "обмен валют", "теннисное табло", "облачное хранилище", "планировщик задач"
- ТЗ каждого проекта описано на соответствующей странице роадмапа для конкретного языка
- Студенты могут сдавать проекты и на других языках, но конкретного ТЗ для них нет

### Работы над роадмапом

- Функционал доступен пользователям с ролью `STUDENT`, вне зависимости от наличия других ролей. 
- Типовой студент выбирает 1 язык и пишет проекты на нём
- Большинство пишет проекты по порядку, но не все. Студенты могут пропускать некоторые проекты, мы их не ограничиваем
- Студент может сдавать проекты на разных языках программирования
- Способы сдать проект описаны тут - [projects-bookkeeping.md](./projects-bookkeeping.md). Их 3 - через UI Mini App, Telegram-бота или импорт. Все реализации независимо от источника участвуют в расчёте прогресса одинаково. Проверка уникальности GitHub URL выполняется среди реализаций из всех источников.
- Один роадмап - один трек, например "Java Backend". Прогресс прохождения роадмапа считается по количеству сданных проектов. В прогрессе завершения роадмапа учитывается количество уникальных типов проектов, для которых студент сдал хотя бы одну реализацию на языке этого трека. Несколько реализаций одного типа на одном языке учитываются как один завершённый шаг.
- Сдача проектов на языках, отличающихся от Java, Go, Python, не засчитывается в прогресс прохождения роадмапа.
- Студент не выбирает тот или иной трек явно. Вместо этого студентам доступны проекты, для каждого из которых существует ТЗ в 3 вариантах (Java, Python, Go). Тем не менее подразумевается, что каждый студент имеет один основной язык, и идет по его треку, отслеживая прогресс. Система не требует у студента выбора трека, но мы можем понять, какой язык изучает студент, исходя из того, на каких языках сданы реализации.

### Шаги работы над проектом

- Для каждого проекта доступно ТЗ для Java, Python, Go
- Студент может сдавать несколько реализаций одного проекта
- Реализация идентифицируется каноническим URL GitHub-репозитория. Каждая реализация имеет один основной язык программирования, который указывает студент. Язык реализации выбирается из справочника с возможностью указать другой язык.
- Перед сохранением GitHub URL приводится к каноническому виду и валидируется на доступность (репозиторий должен быть публичным). Один канонический URL репозитория может соответствовать только одной реализации в системе.
- Опционально, для проекта может быть передана ссылка на деплой (деплой доступен только для проектов "обмен валют", "теннисное табло", "облачное хранилище", "планировщик задач")
- Студент может добавить, изменить или удалить deployment URL после сдачи. Система не гарантирует доступность ресурса.
- Студент не может удалить добавленную им реализацию, но может отредактировать GitHub URL (при условии сохранения уникальности). Изменение GitHub URL применяется только после успешной валидации нового URL. При ошибке ранее сохранённое значение не изменяется.
- Тип проекта и язык реализации изменить нельзя. При редактировании реализации не удаляются её ревью и не сбрасывается прогресс.
